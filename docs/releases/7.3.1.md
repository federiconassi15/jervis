# Jervis 7.3.1

7.3.1 is the first hardening release after the 7.3 runtime-speed rebuild. It adds measurable latency baselines and gives the installer a more deliberate terminal/control-deck identity without adding media-file dependencies.

## Added

- Embedded OpenClaw upstream wizard rendering through Gateway RPC (`wizard.start` / `wizard.next`), keeping the full onboarding flow inside the Jervis installer.
- Schema-driven support for OpenClaw note, text, sensitive text, select, confirm, multiselect, progress, and action steps.
- Dynamic provider/API/plugin coverage: Jervis no longer needs a hard-coded provider list; current and future OpenClaw provider/plugin auth flows appear automatically when exposed by the installed OpenClaw wizard.
- Headless-friendly OAuth/device-code instructions displayed inside the Jervis control deck.

- `jervis benchmark` with text and JSON output for repeatable local DSP, SQLite, and context-snapshot measurements.
- Recent live latency summaries for `inference_ms`, `brain_ms`, and `command_to_reply_ms`.
- A bounded `metrics` state table for runtime performance samples.
- A documented public-release dogfood and soak-test plan covering fresh installs, voice turns, multi-user identity, failure injection, reboot, and long-idle behavior.
- Terminal-native installer cue patterns for boot, installation start, attention/error states, and successful completion.
- Windows console beep tones with a terminal BEL fallback.
- POSIX bootstrap BEL cue before the verified native installer launches.
- `JERVIS_TERMINAL_CUES=0` to disable installer cues and `JERVIS_FORCE_TERMINAL_CUES=1` for explicit nonstandard terminal use.

## Changed

- OpenClaw onboarding now stays behind the Jervis control deck while OpenClaw remains the authoritative source for provider, API, model, channel, search, skill, Gateway, and daemon prompts.

- Version advanced from 7.3.0 to 7.3.1.
- The installer now presents a Unicode-framed Installation Control Deck shell with numbered subsystem stages, stronger status rails, and boxed completion/error states.
- Installer page headings now use numbered control-deck labels for deployment, OpenClaw, audio, identity, review, and installation.
- Bootstrap output now identifies the selected native asset and verified SHA-256 state before launch.
- Normal runtime performance telemetry piggybacks on existing SQLite commits instead of forcing an extra commit on the voice-turn hot path.
- README and roadmap describe the 7.3.x hardening gate before larger 7.4 feature work.

## Removed

- The stale hard-coded `JERVIS 7.1 READY` installer completion banner.
- Reliance on purely prose installer status presentation for major install states.

## Fixed

- Installer completion branding now always uses the active `__version__` rather than an obsolete release string.
- Runtime metrics are bounded and pruned without requiring a per-sample database sync.
- Benchmark state tests use isolated temporary state and do not touch the user's real Jervis database.

## Compatibility

- Installer sounds require no bundled WAV/MP3 assets or extra audio library; they use the host terminal/console mechanisms.
- Terminals that suppress audible BEL may render a visual bell or no cue at all; installation behavior is unchanged.
- Official native binaries remain Rust-accelerated and source installs retain the NumPy fallback.
- 7.3.1 stays on the 7.3 maintenance line and does not introduce a new major/minor compatibility boundary.
