# Jervis 7.3.5

Jervis 7.3.5 is a resilience and recovery release for the 7.3 line. It focuses on making updates, repairs, configuration changes, interrupted installs, and runtime failures reversible before the larger 7.4 feature layer begins.

## Added

- Snapshot system with create, list, restore, retention, metadata, and optional executable capture.
- Automatic snapshots before native updates, install/reconfigure changes, repairs, config migrations, real config edits, backup restore, and uninstall.
- Binary rollback support, including delayed Windows replacement for running executables.
- Verified native self-update using release assets plus SHA256SUMS.
- `jervis update --rollback [SNAPSHOT]` with automatic selection of the latest pre-update snapshot.
- Backup/export and restore commands built on the same snapshot format.
- Versioned configuration migration framework.
- Explicit SQLite schema version gate using `PRAGMA user_version`.
- Crash-session marker and repeated-crash safe-mode escalation.
- `jervis run --safe-mode` to disable proactive delivery, user skills, and OpenClaw routing while retaining local recovery behavior.
- `jervis status` system-status dashboard with service, OpenClaw, acceleration, latency, snapshot, and crash-state information.
- Control Deck `RECOVERY` tab with health, snapshot, and repair actions.
- `jervis repair-center` and snapshot-backed repair for audio, OpenClaw, startup, database, models, and permissions.
- Sanitized diagnostics bundles through `jervis diagnostics` and `jervis doctor --bundle`.
- Permission/capability audit covering Jervis-managed storage, audio/network capability, startup integration, skills location, and the OpenClaw/MCP boundary.
- Install-resume journal that records the last entered setup stage and surfaces interrupted-install continuation.
- Post-install acceptance checks for config, SQLite integrity, startup, OpenClaw, native acceleration, and doctor status.
- OpenClaw compatibility probe for the Gateway RPC interface required by embedded onboarding.
- Bounded benchmark history retained in `benchmark-history.jsonl`.
- Real reinstall flow that removes managed startup integration while preserving user state before relaunching the installer.
- Snapshot-backed uninstall with optional data purge and native binary removal.
- Dedicated upgrade + rollback smoke test gate in GitHub Actions.

## Changed

- Config schema advanced from 1 to 2 with recovery defaults.
- Runtime start events now identify 7.3.5 and safe-mode operation.
- Installer execution snapshots existing Jervis state before mutable host changes.
- Installer progress writes a resume journal and clears it only after successful completion.
- Repair operations use the same recovery snapshot mechanism instead of modifying state without a rollback point.
- Benchmark runs persist the latest 50 reports for comparison and status display.
- Automatic snapshots exclude re-downloadable `models` and `tools` directories while preserving them during restore.
- Diagnostics redact common credential patterns and replace the current home directory with `~`.

## Removed

- Reliance on update-check-only behavior for native maintenance.
- Provider-specific assumptions in recovery/update behavior.
- The expectation that a failed repair, update, or configuration migration must be recovered manually.

## Fixed

- Backup imports now preserve the embedded snapshot identity so restores can locate them correctly.
- Windows snapshot rollback schedules executable replacement after the running process exits instead of attempting an in-place overwrite.
- Crash tracking begins when the runtime actually starts rather than when a Runtime object is merely constructed.
- Re-downloadable model/tool caches are no longer deleted when restoring a mutable-state snapshot.
- Reinstall now removes managed startup integration before launching the installer again.

## Recovery model

Snapshots are intended for Jervis-owned mutable state: configuration, SQLite state, user skills, memory, and related data. Large re-downloadable model/tool caches are intentionally not copied into every snapshot.

Before a destructive rollback, Jervis creates a guard snapshot unless explicitly disabled by an internal recovery operation.

Native binary snapshots are included for update/uninstall recovery when requested.

## Compatibility

- Update automation remains restricted to the current major/minor line: 7.3.x cannot silently become 7.4 or 8.x.
- Official native targets remain Linux x64/ARM64, Windows x64, macOS Intel, and macOS Apple Silicon.
- Source installs retain the portable NumPy fallback; native self-update targets official frozen binaries.
- Windows native updates and binary rollbacks finish replacement after the current process exits because the running executable cannot be overwritten safely in place.
